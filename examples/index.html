Runtime/import behavior

HTML scripts

Put app code in an external or inline script with type="text/jsx" or type="text/babel", then load one Bundless runtime. On document ready, Bundless fetches external scripts or reads inline scripts, transforms the code, and appends module scripts to the page.

Import maps and package imports

Add an import map for bare imports such as react and react-dom. Default imports use bundler-style interop: Bundless binds to the module's own default export when that property exists, and otherwise falls back to the module namespace. Falsy defaults such as false and null are preserved.

Named imports remain strict, namespace imports bind to the module namespace, and side-effect imports load the module without creating a binding. 

<script type="importmap">
  {
    "imports": {
      "react": "https://esm.sh/react@17.0.2/es2022/react.mjs",
      "react-dom": "https://esm.sh/react-dom@17.0.2/es2022/react-dom.mjs"
    }
  }
</script>

Local app modules

Local static imports with .mjs, .js, .jsx, .ts, or .tsx extensions are resolved against the current file and loaded through window.import(). Cache-busting query strings remain part of the module cache key. 

import React from "react";
import Counter from "./Counter.jsx";
import "./analytics.js";

export default function App() {
  return <Counter />;
}

window.import(url)

const module = await window.import("./Dialog.jsx");
module.openDialog();

window.import() normalizes the URL, fetches the source, transforms it, evaluates it as a blob module, and resolves to the module namespace. Concurrent and repeated imports for the same normalized URL share the same promise and resolved module; failed imports are evicted so a later call can retry.

Prefetching

window.Bundless.prefetch(urlOrUrls)

await window.Bundless.prefetch(["./Dialog.jsx", "./Settings.jsx"]);

Use this when you know a module will probably be imported soon. It fetches and warms the source cache only; it does not transform, evaluate, or resolve to a module namespace.

data-bundless-prefetch

<script type="application/json" data-bundless-prefetch>
  [
    "./Dialog.jsx",
    "./Settings.jsx"
  ]
</script>

Use this for startup preparation from HTML. The JSON must be an array of module URL strings. Bundless fetches and transpiles the listed modules without evaluating them; a later window.import() call reuses the prepared code and then evaluates the module.

Runtime choices

Runtime Pick it when Builds
Acorn Use this as the recommended small default for JSX pages. Acorn 36Kb; /dist/bundless.acorn.min.js is the package/browser default and omits runtime inline source maps. /dist/bundless.acorn.prod.js is the Terser-minified production build. /dist/bundless.acorn.dev.js and bundlessdev/acorn/dev include runtime inline source maps for JSX debugging.
Meriyah Use this when you want the alternate JSX parser. /dist/bundless.meriyah.min.js omits runtime inline source maps. /dist/bundless.meriyah.prod.js is the Terser-minified production build. /dist/bundless.meriyah.dev.js includes runtime inline source maps for JSX debugging.
Babel Use this when you need broader Babel standalone syntax coverage in the browser. /dist/bundless.babel.min.js and bundlessdev/babel are the single Babel runtime build. It loads Babel standalone from cdnjs when needed and emits Babel inline source maps.
Sucrase Use this for JSX plus TypeScript or TSX. Sucrase 52Kb; /dist/bundless.sucrase.min.js and bundlessdev/sucrase are the single Sucrase runtime build. It emits Sucrase inline source maps. Load .tsx files with type="text/jsx".

Add to="preact" to the Acorn, Meriyah, or Sucrase runtime tag to target Preact.

<script src="./App.jsx" type="text/jsx"></script>
<script src="/dist/bundless.sucrase.min.js" type="module" to="preact"></script>

Troubleshooting

Modern browser surface

Bundless depends on modern browser features: ES modules, dynamic import(), fetch(), blob module URLs, top-level await, and import maps when you use bare imports.

Production constraints

Runtime transformation means the browser fetches and compiles application source before the app is fully ready. That can be fine for prototypes, small internal tools, docs, demos, and static multi-page apps, but it is real startup work and should be measured on the devices and networks you care about.

Restrictive CSPs may block Bundless because it inserts inline module code and window.import() evaluates transformed modules through blob: URLs. If your runtime, React imports, or application modules come from another origin, your policy also has to allow those fetches and module loads. Cross-origin source files must return CORS headers that allow your page to read them.

Source-map payload

Acorn and Meriyah .dev.js builds include runtime inline source maps for easier debugging. Their .min.js and .prod.js builds omit runtime inline source maps to avoid production size and runtime overhead. Babel and Sucrase have their own single-build source-map behavior, described in the runtime table.

Preact mode

Add to="preact" to a supported Bundless runtime tag to transpile React-style code toward Preact.

  • Preact portals require a concrete DOM element.
  • Preact context consumers need a matching provider.
  • Preact emits regular DOM events; for direct form handlers, read values synchronously from e.currentTarget.value.
  • Refs can differ by pattern; check whether you received a DOM node or a .current object before calling focus().

Babel standalone

The Babel runtime is useful when you need Babel standalone coverage in the browser, but Babel's own standalone docs recommend a Node-based build system for production transpilation. Treat it as a convenience path, then move to Webpack when production constraints show up. The detailed Webpack migration guide lives at bundless.dev/migration.html. Babel standalone docs
