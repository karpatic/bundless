Prefetching

Declarative <script type="application/json" data-bundless-prefetch> lists module URLs that Bundless fetches and transpiles without evaluating; later window.import() calls reuse that prepared code. window.Bundless.prefetch() accepts one URL or an iterable of URLs and warms the source-fetch cache.

Troubleshooting

Preact mode

Add to="preact" to the Bundless script tag to transpile React code toward Preact.

  • Preact portals require a concrete DOM element.
  • Preact context consumers need a matching provider.
  • Preact emits regular DOM events; for direct form handlers, read values synchronously from e.currentTarget.value.
  • Refs can differ by pattern; check whether you received a DOM node or a .current object before calling focus().

ReactDOM imports

Default imports are currently resolved from module.default, so import ReactDOM from "react-dom" can fail. Prefer named APIs such as import { render } from "react-dom" or import { createRoot } from "react-dom/client". Namespace imports such as import * as ReactDOM from "react-dom" are also appropriate for runtime paths that preserve namespace imports.

Babel standalone

You should use a build system running on Node.js, such as Webpack, Rollup, or Parcel, to transpile your JS ahead of time. Babel Docs

Move to Webpack

Bundless is an on-ramp to Webpack: normal application modules can keep literal window.import() calls and supported window.Bundless.prefetch() calls while Webpack takes over resolution and chunking. The plugin does not replace the project's Babel, SWC, esbuild, or TypeScript JSX loader; keep that loader in the normal module pipeline. 

const BundlessWebpackPlugin = require("bundlessdev/webpack");

module.exports = {
  entry: "./src/index.jsx",
  module: {
    rules: [
      {
        test: /\.[jt]sx?$/,
        exclude: /node_modules/,
        use: {
          loader: "babel-loader",
          options: {
            presets: ["@babel/preset-react"],
          },
        },
      },
    ],
  },
  plugins: [new BundlessWebpackPlugin()],
};

Plugin Options

Option Accepted values/default What it does When to use
loader Enabled by default; set exactly false to disable. Adds the Bundless Webpack loader as an enforce: "pre" rule using the configured test, include, exclude, parserPlugins, and prefetch values. Leave enabled for automatic window.import() and window.Bundless.prefetch() transforms. Disable when manually wiring the loader rule.
test Any Webpack rule test value; default /\.[cm]?[jt]sx?$/. Selects the files that receive the pre-loader when loader !== false. Change only when your application stores Bundless calls in a narrower or wider module set.
include Unset by default; any truthy Webpack rule include value. Adds rule.include to the generated pre-loader rule. Use to limit transforms to application source folders.
exclude Default /node_modules/; any truthy Webpack rule exclude value. A falsey override omits rule.exclude. Adds rule.exclude to the generated pre-loader rule. Keep the default for normal apps. Override only when Bundless calls live in code the default excludes.
parserPlugins Unset by default; extra Babel parser plugin entries. Appends parser plugins to the loader's built-in parser set. Resource paths matching /\.[cm]?tsx?$/ also receive the Babel typescript parser plugin. Add when your syntax is not covered by the built-in parser plugins.
prefetch "webpack" by default; "noop". "webpack" turns supported source-level window.Bundless.prefetch() calls into Webpack prefetch hints and a resolved promise. "noop" returns a resolved promise without hints. Use "webpack" for Webpack-managed prefetching. Use "noop" to keep the async call shape without generating hints.
runtime false by default; exact false installs false aliases. Any other value skips alias installation. When exactly false, calls the runtime-alias step so Webpack resolves configured Bundless runtime imports to false. Keep the default after moving runtime work into Webpack. Use a non-false value only if the bundle still needs Bundless runtime imports.
runtimeAliases Unset uses the built-in alias map when runtime === false; a custom object replaces the built-ins. Merges aliases before existing resolve.alias entries, so aliases already present in the Webpack config win. Use only when the default runtime exclusions are too broad or too narrow.
stripHtmlRuntime true by default; set exactly false to disable. Hooks HtmlWebpackPlugin when present. It filters Bundless runtime script tags, Bundless source script tags, and unignored Bundless prefetch tags from HtmlWebpackPlugin tag groups, and removes unignored declarative prefetch script blocks before emit. Leave enabled when HtmlWebpackPlugin is producing HTML that still contains Bundless bootstrap tags. Disable if you intentionally keep those tags.

Default runtime aliases when runtime === false: bundlessdev, bundlessdev/acorn, bundlessdev/acorn/dev, bundlessdev/babel, bundlessdev/meriyah, and bundlessdev/sucrase are aliased to false. Existing Webpack resolve.alias entries win because the plugin aliases are merged first.

HTML Behavior

HTML input Default behavior Important limit
Bundless runtime <script src="...bundless.acorn...js">, babel, meriyah, or sucrase tags in HtmlWebpackPlugin tag groups Removed when stripHtmlRuntime !== false and HtmlWebpackPlugin is present. data-webpack-ignore does not preserve runtime script tags.
Source tags with type="text/jsx", type="text/tsx", type="text/babel", or the matching application/* forms in HtmlWebpackPlugin tag groups Removed when stripHtmlRuntime !== false and HtmlWebpackPlugin is present. The plugin does not turn source script tags into Webpack modules; use normal Webpack entries and loaders.
<script type="application/json" data-bundless-prefetch> blocks Declarative prefetch contents are stripped by default when stripHtmlRuntime !== false. They are not converted into Webpack hints. Source-level window.Bundless.prefetch() calls are what the loader converts.
data-webpack-ignore on a data-bundless-prefetch script Preserves that prefetch block. This escape hatch only preserves prefetch blocks; it does not preserve runtime or source script tags.

Transformer Limits

  • The transformer does not transform calls when window is lexically shadowed.
  • window.import() rewrites its callee to native import() and therefore uses Webpack dynamic-import semantics.
  • Prefetch hints are generated only for a string literal or array literal string entries.
  • Unsupported or dynamic prefetch arguments become a resolved Promise with no hint; prefetch: "noop" also returns a resolved Promise.
  • Transformed prefetch calls do not evaluate modules.

Public API

new BundlessWebpackPlugin(options)

What The default export from bundlessdev/webpack, also available as require("bundlessdev/webpack").BundlessWebpackPlugin.
How Stores options by applying plugin defaults, then overlaying the supplied options object.
When to use Add to plugins for the standard migration path.
Result/important limit Installs behavior only when Webpack calls apply(); it does not replace the app's normal JSX, TypeScript, Babel, SWC, or esbuild loader.

plugin.apply(compiler)

What The Webpack lifecycle method for the plugin. Users do not call it directly.
How Webpack passes the compiler. The method adds the pre-loader unless loader === false, installs runtime aliases when runtime === false, and hooks HtmlWebpackPlugin unless stripHtmlRuntime === false.
When to use Use indirectly by putting a plugin instance in plugins.
Result/important limit Mutates Webpack options and hooks the compilation; it is not an application runtime API.

bundlessWebpack(config, options)

What A named helper export from bundlessdev/webpack.
How Returns a shallow copy of config with new BundlessWebpackPlugin(options) appended to plugins.
When to use Use when a config factory or wrapper style is more convenient than editing the plugins array directly.
Result/important limit It does not deep-merge config objects; it preserves existing plugins by spreading config.plugins || [].

bundlessdev/webpack/loader and require("bundlessdev/webpack").loader

What The package loader export and the loader path exported from bundlessdev/webpack.
How The plugin wires this loader with enforce: "pre". Manual wiring should also use enforce: "pre" so Bundless calls are rewritten before normal transpilation.
When to use Use manually when loader: false is set on the plugin or when the transform needs custom Webpack rule placement.
Result/important limit The loader marks itself cacheable, skips files that do not include the sentinel strings it needs, and returns transformed code only for supported Bundless calls. 
{
  enforce: "pre",
  test: /\.[cm]?[jt]sx?$/,
  exclude: /node_modules/,
  use: {
    loader: require("bundlessdev/webpack").loader,
    options: {
      prefetch: "webpack",
    },
  },
}

window.import(specifier) under the plugin

What A Bundless runtime import call that the loader recognizes in source modules.
How When window is not lexically shadowed, the transformer rewrites the callee from window.import to native import.
When to use Keep existing application calls during migration so Webpack can own the dynamic import.
Result/important limit The resulting call follows Webpack dynamic-import semantics, including Webpack's own handling of specifiers and chunks.

window.Bundless.prefetch(urlOrUrls) under the plugin

What A Bundless source-level prefetch call that the loader can turn into Webpack prefetch hints.
How With prefetch: "webpack", a string literal or array literal string entries become Webpack dynamic imports marked with webpackPrefetch: true, followed by a resolved Promise.
When to use Use for prefetch lists that should become Webpack-managed hints.
Result/important limit Unsupported or dynamic arguments produce a resolved Promise with no hint; prefetch: "noop" does the same. Transformed prefetch calls do not evaluate modules.

Declarative data-bundless-prefetch

What The HTML API used by the browser runtime for declarative prefetch lists.
How The plugin treats matching script tags as Bundless HTML bootstrap content and strips unignored blocks by default.
When to use Keep only when that HTML block is intentionally still needed outside the Webpack hint path.
Result/important limit Declarative prefetch blocks are not converted into Webpack hints. Move wanted hints to source-level window.Bundless.prefetch() calls.

data-webpack-ignore

What An HTML escape hatch for a data-bundless-prefetch script block.
How When the attribute is present on a Bundless prefetch script, the plugin's tag and HTML stripping checks leave that prefetch block in place.
When to use Use for a declarative prefetch block that must survive HtmlWebpackPlugin output.
Result/important limit It only preserves prefetch blocks. It does not preserve Bundless runtime tags, source script tags, or create Webpack prefetch hints.

Migration Checklist

  • Retain normal application imports, literal window.import() calls, and supported source-level window.Bundless.prefetch() calls.
  • Configure a normal Webpack entry and the project's JSX or TypeScript loader.
  • Add new BundlessWebpackPlugin() to plugins.
  • Remove browser bootstrap and source script tags, or let HtmlWebpackPlugin stripping handle generated tags.
  • Migrate declarative prefetch lists to source-level window.Bundless.prefetch() calls when Webpack hints are wanted.
