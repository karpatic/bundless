Bundless Webpack Migration

Move Bundless projects to Webpack when runtime work, dependency control, or deployment policy calls for a build step.

Getting Started | Usage Docs | Playground | GitHub

Move to Webpack

Webpack is the escape hatch: keep literal window.import() calls and supported window.Bundless.prefetch() calls in your app, then add a build when runtime work, dependency control, or deployment policy calls for one. 

const path = require("node:path");
const BundlessWebpackPlugin = require("bundlessdev/webpack");

module.exports = {
  entry: "./src/index.jsx",
  module: {
    rules: [
      {
        test: /\.[jt]sx?$/,
        exclude: /node_modules/,
        use: {
          loader: "babel-loader",
          options: {
            presets: ["@babel/preset-react"],
          },
        },
      },
    ],
  },
  plugins: [
    new BundlessWebpackPlugin({
      include: path.resolve(__dirname, "src"),
      prefetch: "webpack",
      stripHtmlRuntime: true,
    }),
  ],
};

Migration checklist

  • Keep ordinary application imports, literal window.import() calls, and supported source-level window.Bundless.prefetch() calls.
  • Configure a normal Webpack entry and the project's JSX or TypeScript loader.
  • Add new BundlessWebpackPlugin() to plugins.
  • Remove browser bootstrap and source script tags, or let HtmlWebpackPlugin stripping handle generated tags.
  • Move declarative prefetch JSON to source-level window.Bundless.prefetch() calls when Webpack hints are wanted.

How the pieces fit

The plugin is the normal migration path: it adds the Bundless pre-loader, aliases browser runtime imports away by default, and strips Bundless bootstrap tags from HtmlWebpackPlugin output when HtmlWebpackPlugin is present. The loader is only the source rewrite step, useful when you want manual rule placement. Neither the plugin nor the loader transpiles JSX or TypeScript for your bundle; keep your normal Babel, SWC, esbuild, or TypeScript loader.

What happens to source calls?

When window is not lexically shadowed, window.import("./Dialog.jsx") is rewritten to native import("./Dialog.jsx"), so Webpack owns resolution, chunks, and runtime loading. Use literal strings for imports you expect Webpack to split cleanly; dynamic arguments follow Webpack's normal dynamic-import limits.

With the default prefetch: "webpack", window.Bundless.prefetch("./Dialog.jsx") or an array literal of string entries becomes Webpack prefetch hints plus a resolved promise. Unsupported or dynamic prefetch arguments become a resolved promise with no hint, and transformed prefetch calls do not evaluate modules.

What happens to HTML?

With stripHtmlRuntime: true, HtmlWebpackPlugin output drops Bundless runtime script tags, Bundless source script tags, and unignored data-bundless-prefetch blocks. Declarative prefetch JSON is not converted into Webpack hints; move wanted hints into source-level window.Bundless.prefetch() calls. A data-webpack-ignore attribute preserves only declarative prefetch blocks, not runtime or source script tags.

Webpack API reference

Advanced options

loader
Default: enabled because the option is unset. Set exactly false to skip the automatic enforce: "pre" loader rule.
test
Default: /\.[cm]?[jt]sx?$/. Used as the generated pre-loader rule's test.
include
Default: unset. When truthy, copied to the generated pre-loader rule's include.
exclude
Default: /node_modules/. When truthy, copied to the generated pre-loader rule's exclude; a falsey override omits exclude.
parserPlugins
Default: unset. Entries are appended to the built-in Babel parser plugins: jsx, dynamicImport, importMeta, topLevelAwait, classProperties, classPrivateProperties, classPrivateMethods, objectRestSpread, optionalChaining, nullishCoalescingOperator, numericSeparator, logicalAssignment, and importAttributes. Files matching /\.[cm]?tsx?$/ also receive typescript.
prefetch
Default: "webpack". Use "webpack" for Webpack prefetch hints from supported literal calls, or "noop" to keep the promise shape without hints.
runtime
Default: false. When exactly false, the plugin installs runtime aliases to false; any other value skips alias installation.
runtimeAliases
Default: unset. When runtime === false, unset uses the built-in alias map: bundlessdev$, bundlessdev/acorn$, bundlessdev/acorn/dev$, bundlessdev/babel$, bundlessdev/meriyah$, and bundlessdev/sucrase$ all resolve to false. Supplying runtimeAliases replaces that map. The plugin merges these aliases before existing resolve.alias entries, so aliases already in your config win.
stripHtmlRuntime
Default: true. Set exactly false to stop HtmlWebpackPlugin stripping of Bundless runtime tags, Bundless source tags, and unignored declarative prefetch blocks.

Transformer limits

  • The transformer does not transform calls when window is lexically shadowed.
  • window.import() rewrites its callee to native import() and therefore uses Webpack dynamic-import semantics.
  • Prefetch hints are generated only for a string literal or array literal string entries.
  • Unsupported or dynamic prefetch arguments become a resolved Promise with no hint; prefetch: "noop" also returns a resolved Promise.
  • Transformed prefetch calls do not evaluate modules.

Public Webpack exports

BundlessWebpackPlugin

const BundlessWebpackPlugin = require("bundlessdev/webpack");

module.exports = {
  plugins: [new BundlessWebpackPlugin()],
};

This is the standard export and standard use. Webpack calls the plugin lifecycle internally during the build.

bundlessWebpack(config, options)

const { bundlessWebpack } = require("bundlessdev/webpack");

module.exports = bundlessWebpack(
  {
    entry: "./src/index.jsx",
  },
  {
    include: require("node:path").resolve(__dirname, "src"),
  }
);

This helper returns a shallow copy of config with new BundlessWebpackPlugin(options) appended to plugins.

bundlessdev/webpack/loader

module.exports = {
  module: {
    rules: [
      {
        enforce: "pre",
        test: /\.[cm]?[jt]sx?$/,
        exclude: /node_modules/,
        use: {
          loader: "bundlessdev/webpack/loader",
          options: {
            prefetch: "webpack",
          },
        },
      },
    ],
  },
};

Use the loader manually only when loader: false is set on the plugin or when the transform needs custom rule placement.
